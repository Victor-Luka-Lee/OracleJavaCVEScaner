# JVI 아키텍처

## 데이터 흐름

```text
환경/사용자 경로
      │
      ▼
Bounded Discovery ── release/레지스트리/패키지 근거 ──▶ Asset
      │                                                    │
      │                                                    ▼
      └── 오류·범위 통계                     Version Normalization
                                                           │
공식 JSON ── 스키마+SHA-256 검증 ──────────────────────────┤
                                                           ▼
                                             Per-CVE Evaluation
                                                           │
                                                           ▼
                                           CLI / Streamlit / Reports
```

인자 없는 실행에서는 `autorun`이 환경 확인과 보고서 경로 예약을 담당한 뒤 동일한 `workflow`를 호출합니다. `workflow`는 CLI, Streamlit, 자동 모드가 공유하는 `Discovery → Evaluation → ScanReport` 경로입니다.

## 모듈 경계

- `discovery`: 운영체제별 후보 루트를 만들고 제한된 DFS를 수행합니다. 파일/메타데이터를 읽어 `Asset`만 반환하며 CVE를 알지 못합니다.
- `version`: Java 8과 현대 Java 표기를 정규화합니다. 버전 비교와 perf 변형 구분을 한곳에 격리합니다.
- `advisory`: 외부 입력인 JSON을 UTF-8로 읽고, 선택적으로 SHA-256을 확인한 뒤 필수 필드와 중복/검증 상태를 검사합니다.
- `engine`: 하나의 자산과 하나의 CVE를 독립 평가합니다. 공급업체, 제품, 변형, 정확한 영향 버전, 해결 버전 순서로 근거를 좁힙니다.
- `reporting`: 도메인 객체를 직렬화합니다. CSV 수식 주입과 HTML 주입을 방어하며 네트워크 없는 단일 HTML을 만듭니다.
- `workflow`: 탐색, 판정, 보고서 모델 조립을 한 번만 구현하고 CLI/UI/자동 모드가 공유합니다. 제한 도달과 접근 오류를 `incomplete` 및 `limit_reasons`로 보존합니다.
- `autorun`: 인자 없는 무인 실행, 안전한 호스트명/파일명, 실행 위치→사용자 상태 폴더 폴백, 파일 예약, 진행/오류 로그와 자동 모드 종료 코드를 담당합니다.
- `cli`, `ui`: 입력과 표현만 담당합니다. UI 탐색은 백그라운드 스레드와 중단 이벤트를 사용합니다.

## 신뢰 경계

파일 이름, 설치 경로, `release` 내용, 사용자 지정 JSON은 신뢰하지 않는 입력입니다. JVI는 이를 코드로 실행하거나 템플릿에 그대로 삽입하지 않습니다. Java 실행은 기본 비활성화이며 사용자 승인 뒤 발견된 고정 경로를 인자 배열로만 실행합니다. 네트워크 요청 코드와 자동 수정 코드는 포함하지 않습니다.

공식 JSON은 애플리케이션 코드와 분리되어 향후 CVE를 데이터 변경으로 추가할 수 있습니다. 단, 새로운 비교 의미가 필요한 경우에는 엔진 테스트와 함께 명시적으로 코드화해야 하며, “이 버전보다 오래됨” 같은 암묵적 취약 판정은 허용하지 않습니다.

## 판정 보수성

1. 공식 데이터 검증에 실패하면 스캔 자체를 중단합니다.
2. 비 Oracle OpenJDK에는 Oracle 수정 버전을 전용하지 않습니다. 벤더가 식별됐지만 해당 공지가 없으면 `NOT_ASSESSED`, 벤더가 불명확하면 `UNKNOWN`입니다.
3. Oracle 제품이어도 버전 또는 비교에 필요한 세부 build를 확보하지 못하면 `UNKNOWN`입니다.
4. 영향 목록은 정확히 일치해야 `AFFECTED`입니다.
5. Java 8은 update와 build를 독립적으로 비교합니다. 해결 update가 같을 때는 공식 build 이상임을 확인해야 `FIXED`입니다.
6. 공식 영향·해결 목록에 없는 버전은 `NOT_ASSESSED`입니다. 제품 자체가 공식 대상과 명백히 다를 때만 `NOT_AFFECTED`입니다.
